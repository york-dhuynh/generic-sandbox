# Exam guide vs current docs

The exam guides are v1.0 (July 2026). Claude Code ships weekly, so some guide wording is already out of date.

**Rule:** on the exam, answer per the guide, because items are written against it. In real work, follow current docs. If a live exam item looks wrong or has two defensible answers, use Pearson's comment/report feature. It is free and doesn't affect your score. Appeals must be filed within 14 days of the exam date.

Add a row whenever a quiz, lesson, or `/cca-verify` finds a new conflict. Each row needs an official source.

Commands still work, but skills are preferred because they support supporting files. | `.claude/commands/` for a shared command; `~/.claude/commands/` for personal | https://code.claude.com/docs/en/skills |
| 3 | Skill `allowed-tools` | **Restricts** tool access during the skill (e.g., limit to file writes to prevent destructive actions). | **Pre-approves** the listed tools for the invoking turn, so no permission prompt appears. | 4 | Skills and file paths | Sample Q6 rejects skills for convention loading because they "require manual invocation or rely on Claude choosing to load them". Rules with `paths:` remain the documented home for conventions. | `.claude/rules/` with `paths:` globs for conventions | https://code.claude.com/docs/en/skills , https://code.claude.com/docs/en/memory |

| 11 | Few-shot count | 2–4 targeted examples for ambiguous scenarios. | The prompting guide says "Include 3–5 examples for best results." | Don't let the count decide an item. 3 satisfies both | https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices |

Listing Glob or Grep in a subagent's `tools` without Bash brings them back. | Treat Grep and Glob as the built-in search tools, with Grep for contents and Glob for paths | https://code.claude.com/docs/en/tools-reference |
| 13 | Edit on a non-unique match | If Edit fails on a non-unique match, fall back to Read + Write. | `old_string` must appear exactly once. | 14 | Context window as the constraint | Context degradation in long sessions is a core risk. | 15 | Subagent context inheritance | Subagents have isolated context and do not inherit the coordinator's history (tasks 1.2, 1.3). | Still true for normal subagents, which receive only the Agent tool's prompt string. | 16 | Subagent blocking | Parallel subagents = several Task calls in one coordinator response (task 1.3). | Still how parallelism works. Subagents now **run in the background by default** (`status: "async_launched"`), and Claude waits only when its next step needs the report. | Several Task calls in one response | https://code.claude.com/docs/en/agent-sdk/subagents |
| 17 | Skill `argument-hint` | Prompts for required arguments. | A hint shown during autocomplete. Nothing enforces or prompts for the argument; the skill receives an empty `$ARGUMENTS`. | It signals the expected argument; don't rely on it to enforce one | https://code.claude.com/docs/en/skills |
| 18 | Forced `tool_choice` | `tool_choice: "any"` when several extraction schemas exist and the type is unknown. Forced `{"type":"tool","name":…}` to run a specific tool first (tasks 2.3, 4.3). | Not every model supports forced tool use. On **Claude Opus 5.5, Sonnet 5.5, Fable 5.1, and Mythos 5.1**, `any` and `tool` return a 400 error, and manual extended thinking rejects them on any model. | 20 | Tools inside batch requests | Batches don't support multi-turn tool calling within a single request (task 4.5). | Batch requests support tool use. **Server tools** (web search, web fetch, code execution, MCP connector) run in a server-side agent loop inside the batch, and a request can carry earlier turns. **Client** tools still can't execute mid-request, because nothing can send back a `tool_result`. | No mid-request tool loop. Keep agentic, tool-calling work synchronous | https://platform.claude.com/docs/en/build-with-claude/batch-processing |

## Scope differences, not drift

- **Prompt caching:** Foundations needs only "knowing it exists". Professional tests it directly (sample item 2).
- **RAG, embeddings, vector stores:** out of scope for Foundations, but core to Professional P3.5–P3.6.
- **Auth/OAuth:** out of scope for Foundations. Professional P3.2 tests auth gap analysis at the architecture level.
